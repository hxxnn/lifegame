# 라이프 RPG (lifegame) 설계

작성일: 2026-11-07 · 상태: 설계 승인 완료, 문서 검토 대기

## 1. 목적과 성공 기준

삶을 RPG로 바꿔 주는 자기계발 웹앱. 매일 퀘스트를 깨며 스탯을 키우고, 클리어할 때마다 보상이 해금된다. 난이도는 매주 달라진다.

성공 기준:
- 사용자가 매일 앱을 열어 그날의 퀘스트를 체크하고 경험치와 레벨업을 본다.
- 매주 월요일 난이도 테마가 바뀌고, 그 주의 일일 퀘스트가 테마에 맞게 출제된다.
- 클리어를 쌓을수록 장비·칭호·캐릭터·퀘스트·스토리가 열린다.
- 공유 링크/카드로 다른 사람의 캐릭터와 나란히 비교할 수 있다.

## 2. 확정된 결정 사항

| 항목 | 결정 |
| --- | --- |
| 형태 | 웹앱(모바일 브라우저 대응, PWA) |
| 기술 | React + Vite + TypeScript |
| 퀘스트 | 앱이 준비한 퀘스트 풀에서 자동 출제 |
| 스탯 | 힘, 민첩, 지력, 정신력, 행운 (5종) |
| 해금 | 캐릭터 꾸미기 + 스탯 구간별 새 퀘스트/스토리 |
| 저장 | 브라우저 로컬(서버 확장 가능하게 분리) |
| 난이도 | 주간 테마 + 지난주 클리어율 보정 |
| 캐릭터 | 오리지널 8종, 스탯 성향 없음, 주력 스탯은 사용자가 선택 |
| 변경 | 캐릭터와 주력 스탯은 월요일에만 변경 가능 |
| 비교 | 서버 없는 공유 링크/카드 (랭킹은 후속 단계) |

## 3. 구조

- `domain/`: 화면과 무관한 순수 로직(레벨 곡선, 테마 결정, 퀘스트 출제, 해금 판정, 주차 처리). 날짜와 난수는 외부에서 주입한다.
- `data/`: 퀘스트 풀, 캐릭터, 해금 표, 스토리, 밸런스 상수(`balance`). 코드 수정 없이 내용을 늘릴 수 있는 데이터 파일.
- `storage/`: `StorageAdapter` 인터페이스, 로컬 저장 구현, JSON 내보내기/가져오기, 버전 마이그레이션.
- `ui/`: 홈(오늘의 퀘스트), 캐릭터/스탯, 해금 도감, 공유/비교, 설정.

### 플레이어 데이터
- 데이터 버전
- 선택한 캐릭터, 주력 스탯 2개, 닉네임
- 스탯 5종의 누적 경험치(레벨은 계산)
- 주차 기록: 주차 ID, 난이도 테마, 날짜별 출제 퀘스트와 완료 여부, 클리어율
- 해금된 항목 ID, 누적 클리어 수

### 날짜 규칙
- 주는 월요일 0시, 하루는 0시(기기 시간) 기준이다.
- 앱을 열 때 지난 날과 주를 정산하고 새 퀘스트를 출제한다. 앱을 열지 않은 날은 그날의 출제 개수만큼 미완료로 계산한다.
- 시스템 시계가 과거로 돌아가면 되돌리는 갱신은 무시한다.

## 4. 퀘스트·난이도·성장

### 주간 난이도 테마 (월요일 결정)

| 테마 | 일일 퀘스트 티어 | 경험치 배율 | 기본 확률 |
| --- | --- | --- | --- |
| 평온한 주 | 쉬움 위주 | ×1.0 | 30% |
| 보통의 주 | 쉬움~보통 | ×1.3 | 40% |
| 도전의 주 | 보통~어려움 | ×1.6 | 25% |
| 지옥의 주 | 어려움 위주 | ×2.0 | 5% |

- 지난주 클리어율 80% 이상이면 도전·지옥 확률을 올리고, 40% 이하면 평온·보통 확률을 올린다. 첫 주는 기본 확률을 쓴다.
- 클리어율은 지난주 출제된 전체 퀘스트 중 완료 비율이다.

### 일일 퀘스트 (매일 자정 갱신)
- 개수: 월~금 5개, 토·일 7개. 모든 테마가 동일하며, 한 주 총 39개다.
- 티어는 이번 주 테마를 따른다.
- 주력 스탯 2개가 슬롯의 약 60%, 나머지 3개 스탯이 약 40%를 나눠 가진다.
- "매일 고정" 표시가 있는 기본 습관 항목이 하루 1개 포함된다(개수에 포함).
- 전날 출제된 퀘스트는 겹치지 않게 한다. 잠긴 퀘스트는 출제하지 않는다.

### 완료와 경험치
- 체크하면 완료된다. 경험치는 `기본 경험치 × 테마 배율`이고 해당 스탯에 쌓인다.
- 하루 퀘스트를 전부 완료하면 +10%, 주 5일 이상 전부 완료하면 주간 보너스를 준다. 주말에는 7개를 모두 해야 하루 전부 완료로 인정한다.
- 미완료는 스탯을 깎지 않고 클리어율에만 반영된다.

### 레벨 곡선
- 다음 레벨 필요 경험치 `100 × 1.12^(L−1)`. 1→2는 100, 10→11은 277, 20→21은 861, 30→31은 2,676 수준이다.
- 최대 레벨 30. 기본값 100과 비율 1.12는 `data/balance`의 상수다.
- 페이스 목표: 초반 레벨은 며칠, 10레벨은 한두 달, 30레벨은 1년 안팎. 구현 후 실제 값으로 조정한다.

## 5. 해금

1. **누적 클리어 마일스톤(꾸미기)**: 누적 클리어 5, 12, 22, 35개처럼 간격이 점점 벌어지는 마일스톤마다 다음 항목이 하나씩 열린다. 대상은 장비, 칭호, 배경, 새 캐릭터다.
2. **스탯 레벨 구간(콘텐츠)**: 각 스탯이 5, 10, 15, 20, 25, 30레벨에 도달하면 더 어려운 퀘스트 종류와 그 스탯의 스토리 조각이 열린다.

시작 시 선택 가능한 캐릭터는 3종이고, 나머지는 마일스톤으로 해금한다.

## 6. 캐릭터

오리지널 캐릭터 8종(외형과 이름만 있음). 그림은 SVG 벡터로 제작하고, 이미지 파일로 교체할 수 있는 구조로 둔다. 기존 만화·애니메이션 캐릭터는 저작권 때문에 사용하지 않는다.

## 7. 공유와 비교 (서버 없음)

- 설정에서 닉네임을 정한다.
- 공유 시 캐릭터, 닉네임, 스탯 5종 레벨, 주력 스탯, 대표 칭호, 누적 클리어 수를 담은 링크와 PNG 카드를 만든다. 링크에는 압축된 데이터가 들어간다.
- 링크를 열면 내 카드와 나란히 비교한다.
- 값은 조작할 수 있으므로 정보 공유용으로만 쓰고 랭킹·보상과 연결하지 않는다.

## 8. 테스트와 오류 처리

- `domain/`은 Vitest 단위 테스트: 레벨 곡선, 테마 결정, 출제 규칙(개수·비율·중복), 해금, 날짜 경계(월요일 전환, 자정, 며칠 미접속).
- 핵심 화면 흐름은 Playwright로 확인: 체크 → 경험치 → 해금, 공유 링크 → 비교.
- 저장 데이터 손상 시 마이그레이션을 시도하고, 실패하면 백업으로 남기고 새로 시작하며 알린다.
- 잘못되었거나 조작된 공유 링크는 오류 화면으로 처리하고 범위를 벗어난 값은 거른다.
- JSON 내보내기/가져오기로 직접 백업할 수 있고, 설정에서 눈에 띄게 노출한다.

## 9. 1차 범위

포함: 난이도 시스템, 스탯과 레벨, 퀘스트 풀(스탯당 약 20개, 총 100개 안팎), 해금 두 갈래, 캐릭터 8종, 스토리 조각(스탯당 6편), 공유 카드와 비교, 로컬 저장과 백업, PWA.

제외: 서버, 계정, 랭킹, AI 퀘스트 생성, 푸시 알림.

콘텐츠 초안은 개발 쪽에서 작성하고, 사용자가 데이터 파일에서 고칠 수 있게 한다.

## 10. 열린 항목

- 없음. 밸런스 수치(경험치량, 확률, 보너스)는 구현 후 플레이하면서 조정한다.
